================================================================================
 WHY LLM PROMPTING DOMINATED SIMPLETEXT: ANALYSIS OF 2023-2025 WINNING SYSTEMS
                         WITH EVIDENCE FROM OUR RESULTS
================================================================================

1. INTRODUCTION
--------------------------------------------------------------------------------

The CLEF SimpleText task on biomedical text simplification has seen a decisive
shift from fine-tuned encoder-decoder models (BART, T5) to decoder-only LLMs
with prompt engineering. Between 2023 and 2025, every Best-of-Labs paper for the
simplification task used LLMs with prompting as their core approach. This
document analyses why, with real citations from published proceedings and our
own experimental evidence.

3. WHY LLMs OUTPERFORM ENCODER-DECODER MODELS FOR SIMPLIFICATION
--------------------------------------------------------------------------------

This analysis explains the architectural and empirical reasons, supported by
our experimental data.

3.1 Architectural Differences
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Encoder-Decoder (BART, T5, PEGASUS):
- Encoder builds bidirectional representation of input
- Decoder generates output conditioned on encoded representation
- Requires task-specific fine-tuning for every new domain/task
- Output distribution tightly coupled to training data distribution
- Cannot easily incorporate instructions or task framing

Decoder-Only LLMs (LLaMA, GPT, Mistral):
- Autoregressive: predicts next token given all previous tokens
- In-context learning: can adapt to new tasks via prompting alone
- No task-specific fine-tuning needed (zero-shot capability)
- Vast pre-training corpus provides broad world knowledge
- Instruction following: system prompts shape output behaviour

~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

3.3 Three Critical Advantages of LLMs
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

ADVANTAGE 1: Readability (FKGL)
  BART's FKGL of 16.00 is WORSE than the source average of 13.03 — it makes
  text harder to read. LLaMA-8B improves to 11.31. This is because BART is
  trained to compress and rephrase using the SAME vocabulary distribution as
  the source, while LLMs have been exposed to simpler explanatory text during
  pre-training and can draw on that distribution.

ADVANTAGE 2: Deletion Behaviour
  The training set has 35.3% delete labels. BART deletes only 7.3% (a 28-point
  gap), while LLaMA-8B deletes 33.7% (within 1.6 points). LLMs learn the
  operation distribution naturally from the prompt framing, while BART requires
  an external 52% accurate classifier to guide deletion behaviour.

ADVANTAGE 3: Zero-Shot Planning
  Our BART approach required a separate RoBERTa classifier (52% accuracy) to
  predict plan labels. The LLaMA approach integrated planning intrinsically
  through the system prompt. The CLEF 2025 DS@GT paper took this further by
  having the LLM generate explicit structured plans before simplification.

3.4 Where Encoder-Decoders Still Win
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

  BLEU: BART (6.89) vs LLaMA (2.21). BART stays closer to the source, yielding
        better n-gram overlap. For applications requiring high fidelity to the
        original text, encoder-decoder models are safer.

  BERTScore: BART (0.634) vs LLaMA (0.610). LLMs occasionally introduce
             fabricated information or omit key details.

  Computational Cost: BART runs on a single T4 GPU (free Colab). LLaMA-8B
                      requires API calls ($1.60-$6.50 per full test pass).


3.5 Hardcoded Rephrase Hypothesis (New Finding)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

  Our test SARI (34.30) exceeds validation SARI (33.23) by 1.07 points — unusual
  since models typically generalise better on held-out validation data. Evidence
  from BART_TestInference.ipynb suggests a likely explanation:

  The crashed test notebook hardcoded [REPHRASE] for ALL 48,809 sentences,
  bypassing the RoBERTa classifier entirely. If the successful run did the same,
  it means:

  EFFECT 1 — Eliminated 48% classifier error cascade:
    Validation used classifier-predicted labels (52% accurate), meaning ~48% of
    sentences received the wrong plan label. Test used hardcoded [REPHRASE],
    which, while not correct for every sentence, was at least consistent —
    avoiding the catastrophic cases where a delete sentence receives a rephrase
    label and generates verbose output.

  EFFECT 2 — Greedy decoding:
    Test used greedy decoding (num_beams=1) vs validation's optimal beam=2.
    Greedy produces shorter, more conservative outputs that preserve more source
    tokens, potentially boosting SARI keep/deletion components.

  IMPLICATION: The true comparison is not apples-to-apples:
    - Classifier-guided beam search → 33.23 validation SARI
    - No-classifier greedy decoding → 34.30 test SARI
    The 1.07-point gap is plausibly explained by eliminating cascading label
    errors + greedy decoding benefits.

  PRACTICAL INSIGHT: Deploying BART without the classifier would yield higher
  SARI but lose the ability to perform targeted deletion operations (35.3% of
  training data). This represents a fundamental trade-off between raw metric
  optimization and genuine simplification capability.
